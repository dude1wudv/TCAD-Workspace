# 按 run 维护：第一阶段

本阶段提供私有工单入口和有界文件验证，不是新的调度器。未安装监听服务，也未授权任何清理。不要把私有工单行、日志、对象标识或缓存发布到公开 status。

- `maintenance_inventory.py --observation <原心跳> --ledger <原runtime账本> --runs <原runs根> --summary`：只读阶段计数。指定归档的文件逻辑字节不是服务器实释字节；标记存在只选择下一项核验，不证明收据有效。
- `maintenance_journal.py` 使用同样三个输入，另需 `--private-state <独立私有状态目录>`。每个匹配的原 run 持久化一个身份，不按槽复用。SQLite 事务中记录最新观测阶段和不重复的阶段变化事件，旧快照不回滚状态；空快照不代表完成。这个入口没有模型调用、领取权或求解提交权。
- `maintenance_mc2.py` 是可信调用方的专用提取入口，不能将其通用路径参数直接交给模型。只认冻结 MC2 六项合同、成功释放的原 run 和仍在本地的原 tar。原 reader 创建新的数值缓存；核验原始 manifest、输入、归档、提取器版本和回执。已有缓存或无原包时拒绝，不覆盖、不隐式恢复，不发出就绪标记。
- `maintenance_readback.verify_backup` 仅读取已有外存对象，要求匹配配置、上传及保留收据和原 manifest。顺序验证 gzip 字节与解压后原 tar 的长度和 SHA-256，成功返回私有样本报告；不把它写回原运行目录，不执行删除。当前只支持 OAuth 外存模式。它不是完整的科学复演、消费者依赖检查、清理凭证或授权，不替代验收。

上述入口与原控制器、存储 worker、公开快照和训练统计暂时解耦。用于回放的当前观测不证明长期吞吐；保护中的数据不能因为收据文件存在而自动进入清理流程。
