# 清理器验收来源适配 r2

时间细化 A6 已在原作业中完成 4 ns 求解、405 帧提取、全帧审计、匹配 A0 和细化比较，角色 gate 已通过。随后旧清理器要求 gate 必须由旧 `acceptance.py` 产生，不能识别已经冻结的 r1 验收程序，调度因此正常停止。没有创建清理计划、提交清理操作或删除文件。

本修订保存原 r1 发布及失败证据，新增静态清理器版本，仅允许原验收程序或准确绑定 r1 冻结发布的验收程序哈希。科学判据、源归档、提取收据、所有帧哈希、路径检查、远端进程检查和重复 TDR 删除白名单均沿用原实现。未知来源继续拒绝；原 A1 的恢复归档不会因此获得清理许可。

二维调度静态继承 r1，只改用 r2 清理器；验收、调用入口、报告、后处理及三维/输运程序继续使用原冻结 r1 版本。新接续通过 `--adopt r5-a6-b1-time-r1` 复用已通过的 A6 输出与 gate，完成尚未执行的清理，再进入细网格 A1/A5。不重算、不重新验收发布 A6、不增加修复求解次数。

旧 continuation 的退出码 1 和日志保持原样。新 owner 记录位于 `recovery-20261014/continuation-r2/`，复用原 continuation 所有权锁，确认旧 owner 和 scheduler 已退出后才启动。二维全部通过且退出后才启动 r1 三维接续。单 CPU、预算、停止规则和固定输运批次不变。
