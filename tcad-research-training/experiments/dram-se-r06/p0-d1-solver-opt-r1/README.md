# D1 写 1：定位拒步与评估优化

先读已收集的原归档。`diagnose` 可直接读取原 runner 的未压缩 `results.tar` 或单个 `transient_des.log`，只输出 JSON，不解包、不启动求解。以下命令在本目录运行：

```sh
python analyze_ab.py diagnose results.tar --window-ns 30.200 30.925 --open-window
```

按日志打印的 **BE 目标时间** 选试算；默认含两端，`--open-window` 排除两端。打印起止可能相同，步长取原生 `Stepsize`。报告给出接受、拒绝、未完成、覆盖计时的次数，以及拒步消耗的 `Total time`、最耗时拒步的原日志行号和 CNorm 节点。热点计数按每次拒步最后一轮可读 CNorm、每个方程/节点最多一次；原专项审计的末三轮最大项使用另一计数口径。缺少 CNorm 的运行仍可统计拒步。复核该次 P0 已有的原专项审计，勿重复提交 CNorm 任务。

## 已有结果与下一步

2026-11-20 原归档中，WL1 升沿后 `[30.200, 30.925] ns` 的 139 次 CNorm 拒步里，末三轮共 417 次最大误差均来自电子方程。顶点 2264 和 2191 位于 R003 硅与 R009/R011 氧化物交界。静态网格对照中，主热点 2264 的邻近单元比同界面对照更规则；热点本身不足以决定改网格。

用 `diagnose` 对原 CNorm 归档去掉 `--open-window` 可复现：350 次接受、139 次拒步，489 次都有计时。拒步占试算累计耗时的 18,088.02 / 28,696.05 秒（63.0%）。最慢的拒步从日志第 47,970 行开始，耗时 142.59 秒；末轮电子误差最大的位置是节点 2191。按每次拒步的末轮计，节点 2264 共出现 117 次电子方程热点。

已有修复仅在 30.1–32.1 ns 的五段耦合求解加入 `LineSearchDamping=0.25`，保留原网格、源和收敛容差。相同**开区间** `(30.200, 30.925) ns` 的拒步/试算为：历史双核参考 17/76，CNorm 诊断 114/421，局部阻尼 8/57。后者两核跑到 35 ns，31.9 ns 精确读点的 `V(BL)−0.6 V` 为 +26.154030994755 mV。旧参考提前停止，CNorm 诊断止于 30.925 ns；现有对照支持 D1 写 1 零源下的功能观察，受控加速比和阻尼引起的读出变化仍待匹配基线。结果不增加正式样本。

建议沿用已收集的阻尼输入作为 D1 诊断参考。其他条件先运行 `diagnose`，确有相同长尾且影响后续工作时，再选择一次有明确假设的对照。测线性求解器时，`prepare.py BASELINE_PROJECT --variant pardiso_only`（或 `ils2_only`）从冻结输入生成新候选，只改 `SubMethod`，保留线程数、网格、读出电阻、阻尼、终点和完整时间表。原基线可复用；两个旧 `*_damped_r12` 组合保留用于其原用途。生成候选不发布提案。

对已核对同一物理输入、核数、读出协议、相同诊断输出设置的两份完整归档，可分别提取并比较：

```sh
python analyze_ab.py extract baseline.tar baseline.tar --window-ns 30.200 30.925 --open-window --tolerance-ns 0 > baseline.json
python analyze_ab.py extract candidate.tar candidate.tar --window-ns 30.200 30.925 --open-window --tolerance-ns 0 > candidate.json
python analyze_ab.py compare baseline.json candidate.json --stored-bit 1
```

窗口差按候选减基线。缺每步计时则时间差为 `null`；缺读点时仅使用 `diagnose`。应同时检查拒步耗时、整项墙钟、读出方向、裕量差及原生波形。该工具不改变停止条件、线上调度或科学验收。

## 20 核切换草案（未启用）

宿主留 3 核，虚拟机分配 17 核，其中 1 核留给系统、16 核求解。目标是 12 个单核槽加 1 个四核槽，最多同时跑 13 项。调度器按冻结输入的核数匹配槽宽；若队列里还有双核任务，建议先用 10 个单核槽、1 个双核槽、1 个四核槽。等双核任务收集完且队列不再需要该槽，再切目标布局。已有任务沿用原 ID。
