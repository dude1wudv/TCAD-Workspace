# Sentaurus / Geant4 运行

用于通过项目现有 runner 检查、提交、恢复和收集任务。普通计划编写、数据分析和课程整理使用对应技能。

## 按任务处理

- 实际运行时读取项目 `AGENTS.md`、`docs/server-workflow.md`、目标计划和最新交接或状态；只做计划或文档修改时读取必要文件即可。
- TCAD 远端使用 `仿真入口`、`管理入口` 等既有 TCAD 别名，不能把 业务服务器当仿真服务器。服务器本地执行时直接使用现有入口，不重复 SSH 自己。
- 复用 `scripts/tcad.py`、`transport-probe/operation.py`、现有 profile、账本、owner、gate、锁和收集流程，不另建 runner 或求解池。
- 检查或恢复已有任务时先核对 run ID、目录、进程、owner、锁和最新输出。断线优先恢复或收集原任务，不因状态暂时不明而重投。
- 并发对照用 `scripts/batch_runner.py` 读取固定输入清单和 profile。先用 `--dry-run` 核对任务，续接用 `--resume`，每次尝试的日志留在独立目录。上线状态见 `docs/server-workflow.md`。
- 槽位由 profile 的 `cpu_sets` 定义，每槽线程数与分配核心数一致。历史任务沿用原 profile。只有虚拟机明确拒绝预留且确认回滚时才重试原 ID。预留回执不明时保留任务指纹，查原槽位和目录。
- 新任务先冻结输入、源码和参数，保存 SHA256、命令、工具版本，使用新 ID 和独立目录。并发、线程和 CPU 以最新交接和当前 profile 为准，不把历史容量写死到技能里。
- 网格、初始化、电学和提取按实际依赖执行；资源不足时降低并发。保留失败、未收敛和 `FAILED_COLLECTED` 证据，不清锁、不覆盖结果、不手工绕过调度。
- 工程完成、归档完成和科研有效性分别判断。至少记录退出码、收敛或失败原因、数据完整性、输入输出来源、单位及本次适用边界。
- `doctor` 或 `sdevice -v` 可能触发许可证签出，不把它们当成无副作用的目录检查。许可证、密钥、VM 和大型原始结果留在受保护路径。
- 源虚拟机与同身份云副本按最新交接管理，不同时启动；不修改许可证、时间或硬件身份来绕过检查。
- 保留 SSH 主机校验和既有连接身份，不裸连猜测 IP，不把 GitHub 代理变量传入 Tailscale SSH。

## 分工

简单检查、计划落地和普通收集由主代理直接完成。存在清晰独立交付且交接收益明显时，按任务范围派发可复用的子代理，可并行分工，并为每项任务给出输入、写入范围和验收标准。实际求解、队列和共享 runner 始终只有一个调度者，不能为了并行核查而重复派发。

回报当前状态、证据路径、失败和未验证项；没有真实执行的更新、性能或科研结论不写成已完成。
